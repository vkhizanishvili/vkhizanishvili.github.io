# Задел под магазин

Магазин не входит в MVP. Ниже — что уже подготовлено и как его добавлять поэтапно.

## Что уже есть

- **Данные.** У каждой картины есть постоянный `id` (имя файла), числовая цена `price` и статус `status` (`available` / `reserved` / `sold` / `private`). Правила «что можно купить» и «как показать цену» живут в одном месте: `src/_lib/paintings.js` (`priceInfo`, `telegramOrderUrl`).
- **Разметка.** Каждая карточка в галерее содержит `data-id`, `data-title`, `data-price`, `data-status`. Скрипт корзины сможет читать их прямо со страницы, без отдельного API.
- **Этап 1 готов:** кнопка «Заказать» → Telegram с готовым текстом. Включается в админке: *Настройки сайта → Кнопка «Заказать»*.

## Этап 2. Корзина и данные покупателя

1. `src/assets/js/shop/cart.js`: корзина в `localStorage` (оригиналы в одном экземпляре — без количества), кнопка «В корзину» вместо «Заказать», значок корзины в шапке.
2. Страница `src/checkout.njk`: список выбранного, форма (имя, телефон/почта, город, способ доставки, комментарий), согласие на обработку персональных данных со ссылкой на политику.
3. Отправка заявки: бесплатная serverless-функция принимает форму и шлёт уведомление в Telegram-бот или на почту. Токен бота хранится в секретах функции, не на сайте.
4. В `site.json` — переключатель `shop.mode: off | telegram | cart`, чтобы включать режим из админки.

## Этап 3. Оплата

- Провайдер, работающий с самозанятыми или ИП (ЮKassa, Robokassa, CloudPayments и т. п.). Его комиссия (~3–4 %) — единственная неизбежная платная часть.
- Юридически нужны: статус самозанятого/ИП, публичная оферта, страница «Оплата и доставка», политика обработки персональных данных, чеки (54-ФЗ; у многих провайдеров есть встроенная онлайн-касса).
- Схема: сайт → функция создаёт платёж у провайдера → покупатель платит на странице провайдера → вебхук провайдера → функция помечает заказ оплаченным и шлёт уведомление → статус картины меняется на `sold` (вручную в админке или автоматически коммитом через GitHub API).

## Хостинг для магазина

Правила GitHub Pages запрещают использовать его как хостинг интернет-магазина. Перед запуском этапа 2/3 сайт нужно перенести на хостинг, где коммерция разрешена и есть serverless-функции (например, Netlify; выбирать с учётом доступности из РФ на момент запуска). Сборка остаётся той же: `npm run build`, папка `_site`. Админка продолжит работать с тем же репозиторием GitHub.
